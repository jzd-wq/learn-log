# 2026-09-09 学习记录：链表进阶、Maven 与 JUnit

## 今日学习内容

### 一、链表进阶

在之前节点和引用的基础上，继续学习了链表的进阶实现：

- 使用 `SLList` 封装链表结构；
- 使用哨兵节点保存链表的统一入口；
- 使用 `addFirst` 在链表头部添加元素；
- 使用 `getFirst` 获取第一个真实节点的值；
- 使用 `addLast` 遍历链表并在尾部添加元素；
- 使用递归方法计算链表长度。

哨兵节点本身不作为实际数据节点，主要用于简化头节点为空等边界情况的处理。

### 二、Maven 依赖配置

学习了 Maven 项目中 `pom.xml` 的基本结构和依赖配置方式，包括：

- `groupId`：项目或组织的标识；
- `artifactId`：项目名称；
- `version`：项目版本；
- `properties`：统一配置 Java 编译版本和文件编码；
- `dependencies`：声明项目所需要的外部依赖；
- `scope`：控制依赖在哪些阶段和环境中生效。

本次项目引入了 JUnit Jupiter 依赖，并将其范围设置为 `test`，表示它主要用于测试代码，不作为正式业务代码的运行时依赖。

### 三、JUnit 单元测试

学习了使用 JUnit 对方法进行单元测试。本次测试针对 `Main.add(int, int)` 编写了测试用例，并使用断言验证实际结果和预期结果是否一致：

```java
Assertions.assertEquals(3, c, "add failed");
```

### 四、断言

断言用于表达测试预期。常见的断言包括：

- `assertEquals`：判断两个值是否相等；
- `assertNotEquals`：判断两个值是否不相等；
- `assertTrue`：判断条件是否为真；
- `assertFalse`：判断条件是否为假；
- `assertNull`：判断结果是否为 `null`；
- `assertNotNull`：判断结果是否不为 `null`；
- `assertThrows`：判断代码是否抛出了预期异常。

### 五、JUnit 常见注解

本次代码中使用了以下 JUnit 注解：

- `@Test`：标记普通测试方法；
- `@ParameterizedTest`：标记参数化测试方法；
- `@ValueSource`：向参数化测试提供一组简单参数；
- `@BeforeAll`：在所有测试开始前执行一次；
- `@BeforeEach`：在每个测试方法执行前执行；
- `@AfterEach`：在每个测试方法执行后执行；
- `@AfterAll`：在所有测试结束后执行一次。

这些注解可以帮助组织测试生命周期，并减少测试准备和清理代码的重复。

### 六、企业开发规范

了解了企业开发中常见的规范意识，包括：

- 项目结构和命名保持统一；
- 代码需要具备可读性和可维护性；
- 业务代码和测试代码分离；
- 通过自动化测试保证代码质量；
- 使用构建工具统一管理编译、测试和依赖；
- 避免把本地生成文件和 IDE 配置提交到代码仓库；
- 依赖版本和配置尽量集中管理。

### 七、依赖范围

学习了 Maven 中常见的依赖范围：

- `compile`：默认范围，编译、测试和运行时都可用；
- `provided`：编译和测试时可用，运行时通常由外部环境提供；
- `runtime`：运行时需要，编译业务代码时通常不需要；
- `test`：只在测试编译和测试运行时可用；
- `system`：依赖本地文件路径，不推荐在常规项目中使用；
- `import`：主要用于导入依赖管理配置。

## 需要注意的问题

当前参数化测试方法声明为两个参数，但 `@ValueSource` 每次只提供一个整数参数，因此测试方法的参数数量需要保持一致。并且参数化测试方法还需要加入断言，否则即使结果错误，测试也可能不会失败。
